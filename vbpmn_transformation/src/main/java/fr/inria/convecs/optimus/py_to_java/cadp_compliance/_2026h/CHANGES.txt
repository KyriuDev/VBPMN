		in January 2026 (see item #3269 above) has been completed:

		- The three executables evaluator3.a, evaluator4.a, and
		  evaluator5.a have been removed. From now on, evaluator.a
		  remains the only executable for EVALUATOR.

		- The three manual pages "evaluator3", "evaluator4", and
		  "evaluator5" have been removed. Their contents have been
		  merged into the "evaluator" manual page.

		- The three manual pages "mcl3", "mcl4", and "mcl5" have been
		  removed. Their contents have been merged into the "mcl"
		  manual page.

		The "bes" manual page and the CADP web site have been updated
		accordingly.

Nature:		Following the unification of the EVALUATOR executables (see
		items #3270 and #3410 above), SVL does not anymore accept the
		"evaluator3", "evaluator4", and "evaluator5" keywords. Using
		these keywords now triggers a syntax error.

		Also, when verifying an MCL formula, a warning is issued if
		one of the following deprecated variables is defined:
		    $DEFAULT_EVALUATOR3_LIBRARIES
		    $DEFAULT_EVALUATOR4_LIBRARIES
		    $DEFAULT_EVALUATOR5_LIBRARIES
		    $EVALUATOR3_EXECUTABLE
		    $EVALUATOR4_EXECUTABLE
		    $EVALUATOR5_EXECUTABLE
		    $EVALUATOR3_OPTIONS
		    $EVALUATOR4_OPTIONS
		    $EVALUATOR5_OPTIONS

		The SVL manual page and the editor style files for SVL have
		been updated accordingly.

-----------------------------#3412: NOTHING TO DO------------------------------

IMPROVEMENT
Number:		3412
Date:		Fri Jul 17 10:24:35 CEST 2026
Report:		Hubert Garavel (INRIA/ARMADHA)
Authors:	Frederic Lang and Wendelin Serwe (INRIA/ARMADHA)
Files:		bin.*/lnt2lotos, bin.*/traian,
		doc/*/Champelovier-Clerc-Garavel-et-al-10.*

Nature:		The change in semantics for incomplete "case"s in LNT (see
		items #3406 and #3407 above) was completed. From now on:

		- The ".sig" files generated by TRAIAN contain information
		  about incomplete "case"s (if any) present in the source
		  LNT program.

		- LNT2LOTOS uses this information of the ".sig" files to
		  generate LOTOS code that implements the new semantics
		  (i.e., if a "case" is incomplete, one implicitly adds to
		  it an extra branch "any, ..., any -> null").

		The LOTOS code generated for LNT functions and processes that
		contain incomplete "case"s is now different, usually more
		complex. For LNT functions, more LOTOS operations are defined,
		especially operations named CASE__*__FUNCTION_RETURN__*() and
		CASE__*__FUNCTION_RESULT__*(); the LOTOS algebraic equations
		are also different. For LNT processes, the generated LOTOS
		code is larger, so to implement the new branch "any, ..., any
		-> null"; in particular, there is now an extra LOTOS operation
		COMPUTE__CASE__BRANCH_*__CODE__*().

		Obviously, certain LNT programs with incomplete "case"s no
		longer raise an exception at run-time and continue their
		execution. Also, certain warnings about dead code are no
		longer emitted.
